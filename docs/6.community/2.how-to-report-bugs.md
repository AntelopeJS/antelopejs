## Reporting bugs effectively

A report with a minimal reproduction, the expected behavior, the actual behavior and your environment lets a maintainer reproduce the bug on the first try. The steps below build such a report.

## Before you report

### Bug or question?

First, decide which one you have:

- If you need help using AntelopeJS, read [Getting help](/docs/community/getting-help).
- If you found something broken, continue on this page.

If you are not sure, ask on the AntelopeJS [Discord server](https://discord.gg/yS53x6FXQj). If it turns out to be a bug, open an issue for it.

### Check whether it is already known

1. Search the [open issues](https://github.com/AntelopeJS/antelopejs/issues) on GitHub.
2. Search the closed issues for the same problem.
3. If someone already reported it, add your details to that issue instead of opening a new one.

::card{icon="i-ph-magnifying-glass" title="Search tips"}
Search for the exact error message first. If that finds nothing, try other words for the problem.
::

## Creating a good bug report

A bug report needs three things: how to recreate the problem, what happened, and the details of your setup.

### 1. Create a small test case

The most useful part of a report is a small example that shows the bug:

1. Create a new project with only the basics.
2. Add only the code needed to show the problem.
3. Remove anything unrelated.
4. Write down the exact steps that trigger the bug.

A good example:

- Shows one problem
- Has as little code as possible
- Runs without extra setup on a maintainer's machine
- Shows the problem every time

### 2. Share your setup

Give these details about your environment:

| Information          | How to get it                                  |
| -------------------- | ---------------------------------------------- |
| AntelopeJS version   | Run `ajs --version`                            |
| Node.js version      | Run `node --version`                           |
| Operating system     | The name and version of your operating system  |
| Package manager      | npm, yarn, or pnpm, with its version           |
| Related dependencies | The relevant entries from `package.json`       |

### 3. Describe what happened

Describe:

- What you were trying to do
- What you expected to happen
- What happened instead
- The exact error messages, as text and not as screenshots
- The steps that make it happen again

## Submitting your report

When your report is ready:

1. Go to the [AntelopeJS issues](https://github.com/AntelopeJS/antelopejs/issues).
2. Click **New issue**.
3. Choose the **Bug report** form.
4. Fill in every field.
5. Include your test case, or link to a repository that holds it.
6. Add screenshots only if they help explain the problem.

The **Bug report** form asks for the package or repository, the version, a description, a minimal reproduction, the environment, and any additional context. The template below shows what to put in each field.

::card{icon="i-ph-clipboard-text" title="Report template"}

```markdown
**Package or repository**
@antelopejs/core

**Version**
Output of `ajs --version`.

**Description**
What happened, and what you expected instead.

**Minimal reproduction**

1. Set up a project with '...'
2. Add this code '...'
3. Run this command '...'
4. See this error

**Environment**

- Node.js: output of `node --version`
- OS: name and version
- Package manager: name and version

**Additional context**
Logs or other details, with credentials and private data removed.
```

::

## After you report

After you submit:

- Answer the questions maintainers ask on the issue.
- Follow the issue while maintainers investigate it.
- Test the fix when it is released.
- Expect maintainers to work through reported issues in their own order.

## Security issues

Do not report a security problem as a public issue.

::caution{icon="i-ph-lock-key"}
**Do not post security bugs publicly.** Follow the [security policy](https://github.com/AntelopeJS/antelopejs/security/policy) to report them privately.
::
