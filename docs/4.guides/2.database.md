## Prerequisites

Database operations require the `@antelopejs/interface-database-decorators` package. Install it in your module and import from `@antelopejs/interface-database-decorators`.

The [Task API flow](/docs/guides/full-stack-tutorial) shows where a database provider sits behind a controller. The CRUD example here runs directly from a module, so it needs no HTTP server.

:::code-group

```bash [npm]
npm install @antelopejs/interface-database-decorators
```

```bash [yarn]
yarn add @antelopejs/interface-database-decorators
```

```bash [pnpm]
pnpm add @antelopejs/interface-database-decorators
```

:::

The package supplies table metadata and models. Configure a provider of `@antelopejs/interface-database`, such as `@antelopejs/mongodb`, and a reachable database before running these examples. Use a disposable database while learning; schema registration and CRUD examples write data.

## From a table to a stored record

Follow the first pass in this order:

1. [Define a table](#defining-tables), with a schema ID such as `main`.
2. Import that table before [registering the schema](#registering-a-database-schema) in `construct()`.
3. [Create a model](#data-models) and resolve it with `GetModel` after schema registration.
4. [Insert and retrieve a record](#crud-operations) to verify the provider connection.

Indexes, relations and modifiers below extend that working path. A relation describes a link; it does not enforce a foreign key or access policy.

## Defining Tables

You define tables as classes that extend the `Table` base class. The `@RegisterTable` decorator registers the class with the database system under a specific table name and schema. Each property on the class represents a column, declared with the `@Field` decorator.

```typescript [src/db/tables/user.ts]
import {
  Table,
  RegisterTable,
  Field,
  Index,
} from "@antelopejs/interface-database-decorators";

@RegisterTable("users", "main")
class User extends Table {
  @Index()
  @Field("string")
  declare email: string;

  @Field("string")
  declare name: string;

  @Field("number")
  declare age: number;
}

export { User };
```

The first argument to `@RegisterTable` is the table name and the second is the schema name. The `@Field` decorator declares the column type for each property: a primitive token (`"string"`, `"number"`, `"boolean"`, `"date"`), an array (`["string"]`), a nested record, or an io-ts codec. Properties without `@Field` are omitted from the table definition handed to the database adapter. The `@Index` decorator marks a property as indexed for faster lookups.

::note
`Table` is a base class, not a decorator. Always extend it with `class MyTable extends Table`.
::

## Registering a Database Schema

Import the table, then await `RegisterSchema("main")` in `construct()`. It builds the schema from the tables registered under that ID and provisions it through the database provider. The ID must match the second argument of `@RegisterTable`.

```typescript [src/index.ts]
import { RegisterSchema } from "@antelopejs/interface-database-decorators";
import "./db/tables/user";

export async function construct(): Promise<void> {
  await RegisterSchema("main");
}
```

## Data Models

`BasicDataModel(User)` returns a model class with CRUD operations. Extend it when you need application-specific queries, and use `GetModel` to obtain its initialized instance after schema registration. Do not instantiate it with `new`.

```typescript fragment [src/db/models/user-model.ts]
import {
  BasicDataModel,
  GetModel,
} from "@antelopejs/interface-database-decorators";
import { User } from "../tables/user";

class UserModel extends BasicDataModel(User) {
  async getUserByEmail(email: string) {
    const users = await this.getBy("email", email);
    return users.length > 0 ? users[0] : null;
  }
}

export function getUserModel() {
  return GetModel(UserModel);
}

export { UserModel };
```

## CRUD Operations

Add this import and `start()` callback to `src/index.ts`, keeping `construct()` above. The record matches the first User table: `name`, `email` and `age`. Run against a disposable database; this callback writes and deletes a record each time the module starts.

```typescript fragment [src/index.ts (additions)]
import { getUserModel } from "./db/models/user-model";

export async function start(): Promise<void> {
  const model = getUserModel();
  const [id] = await model.insert({
    name: "Alice",
    email: "alice@example.com",
    age: 30,
  });

  const created = await model.get(id);
  console.log("Created:", created?.name); // Alice

  await model.update(id, { name: "Alice Updated" });
  const updated = await model.get(id);
  console.log("Updated:", updated?.name); // Alice Updated

  await model.delete(id);
  console.log("Deleted:", !(await model.get(id))); // true
}
```

Run `ajs project dev`. Expect `Created: Alice`, `Updated: Alice Updated`, and `Deleted: true`. If schema registration fails, check the provider and database connection first. If the table is missing, check the import and schema ID. Stop the process before continuing.

## Model Method Reference

| Instance method | Result |
| --- | --- |
| `get(id)` | One table instance, or no record when the ID is missing |
| `getBy(index, ...keys)` | Records matching an index |
| `getAll()` | All records |
| `insert(data)` | An array of inserted primary keys, not the inserted records |
| `update(id, data)` | Updates a record by primary key |
| `delete(id)` | Removes a record by primary key |

The model class also exposes static conversion methods. `fromPlainData()` creates a table instance from plain data; `fromDatabase()` creates one from storage data; `toDatabase()` converts it back to storage data. These conversions do not themselves read or write the database.

## Indexing

The `@Index` decorator marks a property for database indexing. Indexes speed up queries that filter or sort by the indexed column. You can group multiple columns into a composite index by specifying a group name.

```typescript [src/db/tables/product.ts]
import {
  Table,
  RegisterTable,
  Field,
  Index,
} from "@antelopejs/interface-database-decorators";

@RegisterTable("products", "main")
class Product extends Table {
  @Index()
  @Field("string")
  declare sku: string;

  @Index({ group: "category_brand" })
  @Field("string")
  declare category: string;

  @Index({ group: "category_brand" })
  @Field("string")
  declare brand: string;

  @Field("string")
  declare name: string;

  @Field("number")
  declare price: number;
}

export { Product };
```

Properties with the same `group` value form a composite index. Queries that filter by both `category` and `brand` benefit from the composite index.

## Relations

The `@Relation` decorator declares a link from a field to another table. It is declarative metadata only — database implementations do not enforce it with foreign key constraints — but introspection tooling consumes it to expose the links between tables.

```typescript fragment [src/db/tables/order.ts]
import {
  Table,
  RegisterTable,
  Field,
  Index,
  Relation,
} from "@antelopejs/interface-database-decorators";
import { User } from "./user";

@RegisterTable("orders", "main")
class Order extends Table {
  @Index()
  @Field("string")
  @Relation({ to: () => User })
  declare userId: string;

  @Field("number")
  declare total: number;
}

export { Order };
```

The `to` option is a thunk returning the target table class (lazy, to allow forward references). Use `toField` to point at a field other than the target's primary key, and `many: true` when the field holds an array of target keys.

## Table Modifiers

Modifiers add specialized behavior to table properties. Apply modifiers through `Table.with()`, which returns an extended base class with the modifier capabilities enabled. You can chain multiple modifiers together.

### Hashing

The `HashModifier` enables the `@Hashed` decorator for properties that store hashed values, such as passwords. Hashed values are one-way transformed before storage and cannot be reversed.

```typescript [src/db/tables/user.ts]
import {
  Table,
  RegisterTable,
  Field,
  Index,
  Hashed,
} from "@antelopejs/interface-database-decorators";
import { HashModifier } from "@antelopejs/interface-database-decorators";

@RegisterTable("users", "main")
class User extends Table.with(HashModifier) {
  @Index()
  @Field("string")
  declare email: string;

  @Hashed()
  @Field("string")
  declare password: string;

  @Field("string")
  declare name: string;
}

export { User };
```

When a record is inserted or updated, the `password` field is automatically hashed before it reaches the database. The original plaintext value is never stored.

### Encryption

The `EncryptionModifier` enables the `@Encrypted` decorator for properties that must be stored encrypted. Unlike hashing, encrypted values can be decrypted when read back.

```typescript [src/db/tables/user.ts]
import {
  Table,
  RegisterTable,
  Field,
  Index,
  Encrypted,
} from "@antelopejs/interface-database-decorators";
import { EncryptionModifier } from "@antelopejs/interface-database-decorators";

const secretKey = process.env.DATABASE_ENCRYPTION_KEY;
if (!secretKey || Buffer.byteLength(secretKey, "utf8") !== 32) {
  throw new Error("DATABASE_ENCRYPTION_KEY must contain exactly 32 UTF-8 bytes");
}

@RegisterTable("users", "main")
class User extends Table.with(EncryptionModifier) {
  @Index()
  @Field("string")
  declare email: string;

  @Encrypted({ secretKey })
  @Field("string")
  declare socialSecurityNumber: string;

  @Field("string")
  declare name: string;
}

export { User };
```

Encrypted fields are transparently encrypted on write and decrypted on read. The `secretKey` option is required and specifies the encryption key. You can also configure the `algorithm` (defaults to `aes-256-gcm`) and `ivSize` (defaults to `16`).

::warning
Supply a randomly generated key through your secret-management system before loading the table. For the default algorithm, this API passes the string directly to Node: it must contain 32 UTF-8 bytes, not a 64-character hex encoding of 32 bytes. Keep the same key to read existing records, and plan rotation and recovery before storing data. Do not commit keys or log decrypted fields.
::

### Combining Modifiers

You can apply multiple modifiers at once by passing them all to `Table.with()`. This combination enables both `@Hashed` and `@Encrypted` decorators on the same table class.

Use `class User extends Table.with(HashModifier, EncryptionModifier)` and keep the `@Hashed()` and `@Encrypted({ secretKey })` fields you need from the preceding examples. Hashes cannot be recovered; encrypted fields are decrypted on read, so avoid returning those values indiscriminately from an API.

## Fixtures

The `@Fixture` decorator provides seed data for development and testing. It takes a generator function that returns an array of records to insert when the table is first created.

```typescript [src/db/tables/role.ts]
import {
  Table,
  RegisterTable,
  Field,
  Fixture,
} from "@antelopejs/interface-database-decorators";

@Fixture(() => [
  { name: "admin", permissions: ["read", "write", "delete"] },
  { name: "editor", permissions: ["read", "write"] },
  { name: "viewer", permissions: ["read"] },
])
@RegisterTable("roles", "main")
class Role extends Table {
  @Field("string")
  declare name: string;

  @Field(["string"])
  declare permissions: string[];
}

export { Role };
```

Fixtures run once during schema initialization. They are useful for populating lookup tables, default roles, or any data that must exist before the application starts serving requests.
